# FRONTEND — правила вёрстки

Адаптация регламента NeuroVision (`reference/NEUROVISION_CLAUDE_ORIGINAL.md`) к теме nvglobal.
Там, где тема уже живёт по этим правилам, указано «уже так» — ломать не нужно.
Там, где расходится, указан фактический статус; **исправление идёт через `docs/BACKLOG.md`, не походя**.

---

## 1. Главный принцип

Правим **существующую** вёрстку. Не переписываем блок целиком, если хватает локальной правки.

- Не менять существующие `id` и `data-`атрибуты — на них завязан `js/main.js`.
- Не удалять существующие классы без необходимости.
- Не плодить обёртки, если подходит имеющаяся структура.
- Не вводить новую систему именования и не переименовывать классы.

## 3. Значения и токены

Сначала искать готовое: цвет, радиус, размер шрифта, отступ, тень, размер кнопки.
Новое значение — только когда аналога объективно нет.

### ⚠️ Особый случай темы: `var()` без объявлений

В `styles.css` 384 обращения к 11 токенам (`--island-*`, `--stroke-*`, `--text-*`,
`--range-*`), и **ни один из них не объявлен**. Работают fallback’и.

Что это значит на практике:

- **Не объявлять `:root { --island-…: … }`** — это молча перекрасит до 106 мест сразу.
- Новый код пишет **то же самое выражение целиком**, вместе с fallback:
  `var(--island-white-5, rgba(251, 251, 251, 0.05))`.
- Перед использованием токена — свериться с `docs/THEME-TODO.md`: у пяти имён
  fallback’и расходятся, и «правильного» значения у них сейчас нет.

Приведение токенов к единому виду — отдельная задача (`docs/REFACTOR_PLAN.md`, этап R3).

## 4. Типографика

- `font-size` — в пикселях, по макету.
- `line-height` — **только в `%` (предпочтительно) или множителем**, никогда не в px.
  Расчёт: `line-height ÷ font-size × 100`. Пример: `40px / 48px` → `line-height: 120%`.
- В теме уже 0 вхождений `line-height` в px — не ломать.

### Неразрывный пробел

Тексты сайта **английские**. Правила склейки из регламента NeuroVision написаны под русский
(предлоги `в, к, о, с, у`, частицы `бы, же, ли`) — **к английскому не применяются**.

Для английского ставить `&nbsp;` только там, где перенос реально уродует строку:

- между числом и единицей: `195&nbsp;countries`, `10,000&nbsp;checks`, `24/7`;
- в коротких неразрывных парах: `KYC&nbsp;/&nbsp;AML`, `Face&nbsp;ID`;
- перед висящим однословным хвостом заголовка.

Не склеивать служебные слова поголовно и проверять результат на 375px — длинные склейки
рвут узкую колонку. Сейчас в шаблонах 38 вхождений `&nbsp;`.

## 5. Раскладка

**Flexbox — основной инструмент.** В теме 396 `display:flex` против ~8 мест с Grid.

- Ряды, карточки, колонки, адаптивные перестроения, Swiper — через Flexbox.
- Сетки карточек: `flex-wrap: wrap` + `flex: 0 0 calc((100% - 32px) / 3)`.
- Grid **не вводить** в Hero, Cards, Features, Products, Logos, Testimonials, Blog, Footer.
- Grid допустим только когда Flexbox объективно усложняет код — **сначала объяснить и получить согласие**.

**Существующий Grid не переписывать на Flex в рамках обычной задачи.** Он есть в
`video-intro`, `solutions`, `cases` и ещё нескольких местах, работает, миграция — это
рефакторинг (см. `docs/BACKLOG.md`).

## 6. Кнопки

- Текстовым кнопкам — **`min-height`, не `height`**. Кнопка должна расти при переносе текста.
- Габариты по макету добираются `padding` + `box-sizing: border-box`.
- Фиксированные `height`/`width` допустимы только для квадратных иконок-кнопок (40×40, 56×56).

Известное отклонение: `.btn-hero` имеет `height: 64px` (`styles.css:1100`).
Не копировать этот приём в новый код; правка самой кнопки — через `docs/BACKLOG.md`.

---

## 7. Декоративные absolute-изображения

- Заранее резервировать место (`padding-right` / `padding-bottom`), считая от
  **проанализированной** ширины изображения и его смещения. Значение комментировать, а не угадывать.
- Текст и кнопки **никогда** не заходят под absolute-картинку.
- Проверять промежуточные ширины, а не только брейкпоинты, — там контейнер уже, а картинка та же.
- Если картинка выходит за блок — смещение (`top`/`right`) + `overflow: hidden`
  на контейнере изображения. Размеры самой картинки не трогать, кадрирует контейнер / `object-fit`.
- «Выступает сверху и обрезается снизу» — обёртка, растянутая `top`+`bottom`, с `overflow: hidden`;
  сам блок `overflow: visible`. (`<img>` — replaced-элемент, парой `top`+`bottom` не тянется.)

## 8. SVG-иконки

Интерфейсные иконки (стрелки, chevron, plus/minus, check, крестик, search, burger,
play/pause, download, calendar, соц-иконки) — **inline `<svg>` в разметке**.

- `fill="currentColor"` / `stroke="currentColor"`, цвет только через CSS `color`.
- Анимация — через CSS (`transform`, `opacity`), не подменой файла.
- Размер — классом на `<svg>`; `viewBox` сохранять.
- Декоративным: `aria-hidden="true" focusable="false"`.
- **`<img src="icon.svg">` для интерфейсных элементов не использовать.**

`<img>` остаётся для логотипов, фотографий, сложных иллюстраций, самостоятельной графики.

**Перед добавлением иконки — искать её в проекте.** В шаблонах уже ~98 inline-SVG
на главной и ~60 на `/solutions/`. Нашлась такая же — переиспользовать **тот же код**
(идентичные `viewBox` и `path d`), дубликат-вариант не создавать.

### Перенос SVG из Figma — сохранять геометрию

**Обязательно сохранять:** исходный `viewBox`, `width`/`height`, координаты `path d`,
внутренние поля внутри `viewBox`, влияющие `clipPath` / `mask` / `defs`.

**Запрещено:** пересчитывать `viewBox` по границам path, обрезать пустые поля,
масштабировать path вручную, менять координаты, переносить иконку в другой `viewBox`.

**Разрешено:** заменить фиксированный `fill`/`stroke` на `currentColor`; удалить
`clipPath`/`defs`, только если визуально ничего не меняется и это проверено;
сделать `id` внутри `defs` уникальными при повторе иконки на странице.

#### Ловушка `get_design_context`

MCP часто отдаёт **обрезанный** SVG: одиночный `<path>` с `viewBox` по габаритам глифа
(например `viewBox="0 0 5.92858 10.6667"`) вместо родного квадратного кадра `24×24` с полями.
Вставленный в слот 24×24, такой глиф растягивается от края до края и не совпадает с макетом.

- Не копировать `viewBox` из вывода MCP вслепую.
- Признак обрезки: `viewBox` не квадратный или подозрительно «тесный».
- Брать кадр иконки-компонента из Figma либо восстановить квадратный `viewBox`
  с теми же внутренними отступами. Глиф на весь кадр не растягивать.
- После вставки — смотреть в браузере, что доля глифа в кадре та же, что в макете.

## 9. Растровые изображения

Выгружать **самому** — это шаг пайплайна, а не повод просить файл у пользователя.
Просить только когда источник объективно недоступен.

**Источник — чистая нода изображения / image-fill, не скриншот блока.** В композите
запечены оверлеи, градиенты, тени и компрессия.

Порядок: (1) выгрузить ноду слоя через MCP по node-id из присланных ссылок секции;
(2) если MCP не отдаёт — запросить экспорт **именно этого слоя** с указанием node-id,
явно сказав, что композит блока не подойдёт.

### Формат и имена

- Растр — **x1 + x2**: `name.webp` + `name@2x.webp`. x3 не делаем.
  x1 = размер слота по макету, `@2x` — вдвое.
- Фото и иллюстрации — WebP lossy q≈82. Логотипы и иконки с альфой — WebP lossless.
- В `<img>`: `srcset="….webp 1x, …@2x.webp 2x"` + явные `width`/`height` + осмысленный `alt`
  (декоративным — `alt="" aria-hidden="true"`).

### ⚠️ Куда класть — в теме иначе, чем в регламенте

Регламент NeuroVision требует `img/<секция>/` и `img/source/`. В теме nvglobal
**`img/` плоский** (подпапки только `industries/` и `favicon/`), имена вида
`products-image1.jpg`, `cases__item-image.png`, `advantages__maskot.png`.

До отдельного решения (`docs/REFACTOR_PLAN.md`, этап R2) — **класть новые файлы
в `img/` по существующей схеме имён `<блок>__<роль>.webp`**. Новых каталогов
активных ассетов не заводить.

Перед выгрузкой — проверить, нет ли такого ассета. В `img/` уже ~50 MB вытесненных
оригиналов, дубли умножать не нужно.

Правильного ассета пока нет — пометить `src` как placeholder и сказать об этом,
но геометрию слота (размеры, `object-fit`, `object-position`) выставить по макету,
чтобы финальный файл встал без переверстки.

## 10. JavaScript

- Не менять бизнес-логику, не переименовывать функции, не снимать обработчики без необходимости.
- Не ломать калькулятор, табы, слайдеры, формы и AJAX.
- Новый код — в `js/main.js`, рядом со своим компонентом. В `main.js` 31 инициализатор
  вида `initXxx()`, держаться этой схемы.

### Доступность интерактива

Табы: `role="tablist"` / `role="tab"` / `role="tabpanel"`, `aria-selected`,
`aria-controls` + `aria-labelledby`, `hidden` на неактивных панелях,
roving tabindex (активная `0`, прочие `-1`), клавиши ←↑→↓ / Home / End.

Тот же подход — аккордеонам, модалкам, дропдаунам, слайдерам.

> Факт: в теме полный ARIA есть только у Gutenberg-блока `blocks/tabs/tabs.php`.
> Собственные табы (`initDocTabs`, `initFeaturesBlock`, `initBenefitsSlider`) его не имеют.
> **Новые компоненты делаем правильно сразу**; дооснащение старых — `docs/BACKLOG.md`.

### Состояние карточек

Не использовать `:hover` единственным способом переключения состояния карточки.
Состояние — классом (`.is-flipped`), который ставит JS:

- есть hover (`@media (hover: hover)` / `matchMedia('(hover: hover)')`) → `mouseenter` / `mouseleave`;
- нет hover (`(hover: none)`) → `click` (toggle).

Ключ — **наличие hover**, не ширина экрана и **не `pointer: fine`**: последнее отсекает
сенсорные и гибридные десктопы. В `styles.css` есть два правила
`@media (hover: hover) and (pointer: fine)` — это известное отклонение, в новый код не копировать.

Простую подсветку кнопок и ссылок можно оставлять на CSS `:hover` — правило про состояние карточек.

## 11. Переиспользование

1. **Компонент.** Отличается только размерами / цветом / отступами / типографикой →
   расширяем существующий **модификатором**. Новый компонент — только при другой
   структуре, логике или назначении.
2. **Модификатор.** Любой новый (`.btn--sm`, `.card--…`) сначала обосновать:
   проверил существующие → почему не подходят → только потом создаю.
3. **SVG.** Есть такая иконка — берём её, дубликат не плодим.
4. **Дизайн-система.** Перед новым цветом / радиусом / шрифтом / тенью / отступом —
   проверить, нет ли уже такого.

Каталог готового — `docs/COMPONENTS.md`.
