## 1. ⚠️ Необъявленные CSS-токены — главный риск темы

### Что есть

В `css/styles.css` **384 обращения `var(--…)`** к **11 именам токенов.
Ни одно из них не объявлено** — ни в `:root`, ни где-либо ещё в теме.
Проверено в браузере: `getComputedStyle(document.documentElement)
.getPropertyValue('--island-white-5')` возвращает пустую строку.

Везде работает fallback, второй аргумент `var()`:

```css
background: var(--island-white-5, rgba(251, 251, 251, 0.05));
```

Единственные настоящие объявления в теме — 5 локальных `--toc-depth-offset`
в `css/document-toc.css`, к этой истории отношения не имеют.

### Частота

| Токен | Обращений |
|---|---|
| `--stroke-white-15` | 106 |
| `--island-white-5` | 59 |
| `--text-white-70` | 37 |
| `--island-orange-20` | 20 |
| `--island-white-10` | 19 |
| `--text-white-50` | 17 |
| `--stroke-white-10` | 7 |
| `--range-progress` | 3 |
| `--stroke-black-10` | 2 |
| `--text-black-70` | 1 |
| `--range-value-shift` | 1 |

### Почему нельзя просто объявить их в `:root`

**У пяти токенов fallback’и расходятся — одно имя, разные значения:**

| Токен | Встречающиеся значения |
|---|---|
| `--text-white-70` | `rgba(251,251,251,0.7)`, `rgba(251,251,251,0.70)`, `rgba(255,255,255,0.70)` |
| `--stroke-white-15` | `rgba(251,251,251,0.1)` и `rgba(251,251,251,0.15)` |
| `--island-white-5` | `rgba(251,251,251,0.05)` и `rgba(251,251,251,0.15)` |
| `--island-white-10` | `rgba(251,251,251,0.10)` и `rgba(251,251,251,0.30)` |
| `--island-orange-20` | `rgba(249,170,102,0.2)` и `rgba(249,170,102,0.20)` |

Сейчас каждое место живёт со своим значением и выглядит как задумано.
Стоит объявить `--stroke-white-15` — **все 106 мест разом возьмут одно значение**,
и там, где fallback был другой, цвет станет неверным. Сайт поедет молча:
ни ошибки в консоли, ни предупреждения сборки.

`--island-white-5` с разбросом 0.05 ↔ 0.15 — втрое по альфе. Это заметно.

### Правило до разбора

- **Не объявлять `:root { --island-…: … }`.**
- Новый код пишет выражение целиком, вместе с fallback.
- Нужен точный цвет — брать fallback из конкретного места, а не из имени токена:
  имя `--stroke-white-15` не гарантирует альфу `0.15`.

### Как разбирать, когда дойдут руки

Разбор по одному токену за раз, снизу вверх по частоте — начинать
с `--text-black-70` (1 место), не с `--stroke-white-15` (106).

Порядок на каждый токен:
1. Выписать все вхождения и их fallback’и.
2. Для расходящихся — определить по макету Figma, какое значение правильное,
   а какое было опечаткой.
3. Там, где значение должно отличаться осознанно, — завести **отдельное имя**.
4. Объявить токен в `:root` и убрать fallback’и **только у приведённых к одному значению**.
5. Скриншот-сверка затронутых секций до и после, на 1920 / 840 / 375.

Общая оценка — `docs/REFACTOR_PLAN.md`, этап R3. Это самый дорогой и самый рискованный
пункт всего плана.
