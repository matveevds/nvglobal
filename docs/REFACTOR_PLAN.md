# REFACTOR_PLAN — предложение

> **Статус на 2026-10-05: решения приняты, см. `docs/DECISIONS.md`.**
> Ни один PHP, CSS или JS-файл темы не изменён.
>
> | Этап | Решение |
> |---|---|
> | R1 изображения | **отложен** до конца редизайна; выполнена точечная чистка 1 файла |
> | R2 дубли шаблонов | **не выполнять**, `main-page-video-autoplay.php` остаётся |
> | R3 токены | **отложен** до получения Figma |
> | R4 мёртвый JS | GLightbox **не восстанавливать**; остальное не начато |
> | R5 мелкие дефекты | `info.svg` ждёт решения; ACF-группа оставлена как есть |
> | R6 регламент | **не отдельным этапом** — постепенно при редизайне |

Цель — убрать то, что будет мешать вёрстке по Figma, не трогая внешний вид сайта.
Этапы отсортированы по соотношению «польза / риск»: R1 почти безопасен, R6 дороже всего.

---

## Общие правила для любого этапа

1. **Точка отката до начала.** Рабочее дерево чистое → `git commit` текущего состояния,
   затем ветка `refactor/<этап>`. Откат — `git revert` коммита этапа. Никаких
   `git reset --hard`, `git clean`, `git checkout --`.
2. **Baseline до и после.** Скрипт из `docs/QA.md` раздел 3, четыре страницы × пять вьюпортов.
   Сверять: высоту документа, отсутствие горизонтального переполнения, число ошибок консоли.
3. **PHP-линт** всех файлов до и после.
4. **Один этап — один коммит.** Не смешивать с правками вёрстки и с чужими изменениями.
5. **Push только по прямому указанию.**
6. Любое изменение CSS или JS → поднять `THEME_ASSETS_VER` (`functions.php:16`).

## R1. Неиспользуемые изображения — ОТЛОЖЕН (Р-1)

> **Решение:** полная чистка откладывается до конца редизайна. Массовый перенос
> в `_unused/` отменён. Сейчас допустима только очистка **доказанных дубликатов**
> с проверкой ссылок и зависимостей.
>
> **Выполнено 2026-10-05:** удалён `img/flow_step1 (1).png` (45 KB, побайтовая копия,
> ноль ссылок). Больше ничего под критерий не подошло.
>
> ⚠️ Проверка попутно выявила, что 31 файл `*.png.webp` — **живые WebP-двойники
> Seraphinite**, а не мусор. Их удаление было бы невидимой регрессией на проде.
> Текст ниже сохранён как методика для будущей чистки.

**Польза:** `img/` 62 MB → ожидаемо ~12 MB. Быстрее git, быстрее заливка на прод.
**Риск:** низкий, **но только после второй проверки.**

### Что нашёл аудит
Поиск по имени файла в `*.php`, `*.css`, `*.js` не дал ссылок примерно на 50 MB:
`main-solutions-bg.png` (28 MB), `main-solutions-bg.svg` (10 MB),
`features__tab--maskot.png` (3.4 MB), `cases__item-image.png` (1.5 MB),
`case_image_sound.svg` (1.4 MB) и ещё ~25 файлов помельче.
В CSS используется только `main-solutions-bg3.webp` (140 KB).

### Почему нельзя удалять сразу
Проверка велась **по коду темы**. Не проверены:
- содержимое записей и страниц в БД (`post_content`), особенно 71 документ CPT `document`;
- мета-поля ACF, хранящие пути;
- `wp-content/uploads/` и другие темы;
- ссылки, собираемые в JS конкатенацией.

### Порядок
1. Скрипт: для каждого кандидата искать имя в `wp_posts.post_content`,
   `wp_postmeta.meta_value`, `wp_options.option_value`.
2. Чистых кандидатов — **не удалять, а перенести** в `img/_unused/`
   (служебный каталог, в вёрстке не используется).
3. Прогнать baseline из `docs/QA.md` + пройти страницы глазами.
4. Неделю не трогать. Ничего не всплыло → удалить каталог отдельным коммитом.

### Откат
Файлы лежат в `img/_unused/` до финального удаления — возврат мгновенный.
После удаления — `git revert`.

## R3. CSS-токены — ОТЛОЖЕН до Figma (Р-5)

> **Решение:** разбор откладывается до получения макетов. Существующие переменные
> с конфликтующими fallback-значениями **глобально не объявлять**.
> Это совпадает с рекомендацией ниже.

**Польза:** появляется настоящая дизайн-система — без неё смена палитры по Figma
превращается в 384 точечные правки.
**Риск:** **высокий.** Самый дорогой пункт плана.

384 обращения `var()` к 11 необъявленным токенам; у пяти fallback’и расходятся
(`--island-white-5` — разброс альфы 0.05 ↔ 0.15, втрое).
Полный разбор — `docs/THEME-TODO.md`, раздел 1.

### Порядок — по одному токену за раз, снизу вверх по частоте
Начинать с `--text-black-70` (1 вхождение), **не** с `--stroke-white-15` (106).

На каждый токен:
1. Выписать все вхождения с fallback’ами.
2. Для расходящихся — определить по Figma, какое значение верное, а какое опечатка.
3. Осознанно разные значения → **отдельное имя токена**.
4. Объявить в `:root`, fallback’и снять **только у приведённых к одному значению**.
5. Скриншот-сверка затронутых секций до/после на 1920 / 840 / 375.

### Рекомендация по срокам
**Делать не раньше, чем придут макеты Figma.** Сейчас не из чего определить,
какое из расходящихся значений правильное — только угадывать. С макетом это
становится механической работой.

### Откат
Покоммитно, по одному токену. Поехал цвет — `git revert` одного коммита.
