## 1. Задача

Ты собираешь новые страницы сайта nv.global **из уже готовых блоков** темы по ТЗ владельца.

- **Вход:** ТЗ страницы — `/Users/dmitriy/ZAKAZI/nv.global/ТЗ на новые страницы/ТЗ страница «<Название>» nv.global.md`
  (рядом `.docx` той же структуры — не нужен). Владелец называет страницу, ты находишь файл.
- **Что делаешь:** выбираешь в библиотеке блоков подходящие под каждый блок ТЗ, ставишь их на
  страницу в порядке ТЗ и заменяешь в них заголовки, подзаголовки, тексты, списки, кнопки,
  картинки, alt, якоря — новым контентом из ТЗ.
- **Выход:** шаблон страницы `page-<slug>.php` в корне темы (один самостоятельный файл),
  при необходимости картинки `img/<slug>-*.webp`, карта страницы `docs/pages/<slug>.md`,
  запись в `docs/CHANGELOG.md` и отчёт владельцу с пакетом для прода.
- **Дальше — владелец:** заливает файлы на прод по FTP, в админке создаёт страницу, выбирает
  твой шаблон в «Атрибуты страницы → Шаблон», заполняет Yoast. Ты на прод ничего не делаешь.

Ты **не** дизайнер и **не** верстальщик: новых блоков, новых стилей и правок существующих
блоков не делаешь. Если ТЗ нельзя выразить имеющимися блоками — останавливаешься и спрашиваешь (§10).

## 2. Как устроена собранная страница

Механизм — `inc/page-builder.php` (подключён в `functions.php`, трогать не нужно).

**Шапка файла шаблона** — два обязательных заголовка:

```php
<?php
/*
Template Name: AML Screening
Template Post Type: page
NV Page Family: identity
*/
```

- `Template Name` — то, что владелец увидит в списке шаблонов админки. Название продукта по-английски.
- `NV Page Family` — **семейство оформления**: `identity`, `kyc` или `solutions`. Странице добавляется
  body-класс шаблона-источника (`page-template-page-identity-verification` и т. д.). Через него
  работают ≈640 правил вида Identity, светлые шапка / подвал / Contacts / FAQ, светлая тема
  (`nv_is_light_theme()`) и отступы между блоками (`--nv-block-space`). Без этого заголовка
  страница развалится. Регистрировать шаблон где-то ещё **не нужно и нельзя**.

**Выбор семейства:** берёшь то, из чьих блоков состоит большая часть страницы. Продуктовые
страницы (AML, Liveness, Face, Document, KYB, KYT, Age, NeuroPay) — как правило `identity`:
у Identity самый полный и самый новый набор. `kyc` — если основу дают KYC-only блоки
(Risk, Compliance, SEA-табы, Onboarding). `solutions` — для отраслевых/обзорных страниц
(Banks, Crypto, FinTech, Industries), если основа — блоки /solutions/.
**Одно семейство на страницу.** Блок чужого семейства — только после проверки в предпросмотре (§12).

**Скелет файла:**

```php
get_header();
require_once get_template_directory() . '/inc/identity-icons.php';   // иконки, которые нужны блокам
require_once get_template_directory() . '/inc/kyc-icons.php';
require_once get_template_directory() . '/template-parts/contacts-icons.php';
$nv_img   = get_template_directory_uri() . '/img/';
$nv_arrow = nv_contacts_icon('arrow', 24);
$nv_page_img = static function (...) { ... };   // копия помощника $nv_idv_img из page-identity-verification.php

/* Весь контент страницы — здесь, одним массивом, в порядке блоков ТЗ. */
$nv_page = array(
    'hero' => array('title' => '…', 'subtitle' => '…', /* … */),
    // …
);
?>
<main>
    <?php /* 1. Hero (ТЗ, блок 1) — template-parts/kyc-hero-section.php */ ?>
    …
</main>
<?php get_footer();
```

Контент держи в самом шаблоне (`$nv_page`), а не в отдельном `inc/*-data.php`: владелец заливает
на прод один файл. Комментарий над каждой секцией: номер и название блока ТЗ + откуда взят блок.

**Предпросмотр без создания страницы в БД** (только администратор, остальным 404):
`https://nvglobal.local/kyc/?nv_page_preview=page-<slug>.php` — страница /kyc/ на время запроса
получает твой шаблон. Заголовок вкладки и Yoast-мета остаются от /kyc/ — это нормально.
Главную как основу не используй (класс `home` исказит вид). Страницы в БД не создавай.

### 3.1. Блоки для сборки

Два способа поставить блок:

- **P — partial.** `get_template_part('template-parts/<file>', null, array(...))`. Аргументы описаны
  в шапке файла partial. **Передавай каждый текстовый аргумент явно.** У универсальных блоков (отмечены в
  таблице) зашитых текстов нет: значения по умолчанию пустые, необязательное не передают — оно не выводится.
  Исключения — Integration (стандартный набор `nv_integration_preset()`) и Contacts / FAQ (прежние тексты
  по умолчанию, если аргумент не передан).
- **C — копия секции.** Секция, которая ещё живёт прямо в шаблоне-источнике (Process, Coverage, Onboarding,

  в свой шаблон **без изменения структуры**: те же теги, классы, `data-*`, `aria-*`, порядок
  элементов; меняешь только текст, URL картинок, alt, `id`/якоря и число повторяющихся
  карточек. Источник не трогаешь. Данные секции (циклы `foreach` по `$nv_idv[...]`) переводишь
  на свой `$nv_page[...]`.

## 4. Сопоставление ТЗ → блоки

Для каждого блока ТЗ («### Блок N. …») выбери блок библиотеки по **смыслу и форме контента**:
число карточек, есть ли табы, шаги, карта, цены, форма. Критерии по убыванию:

1. Форма контента совпадает (4 шага → How it works; 3 уровня с табами → Risk-Based; список
   вопросов → FAQ; таблица требований по странам → Compliance Map или SEA-табы).
2. Блок из выбранного семейства.
3. Количество элементов: можно менять число повторяющихся карточек/шагов/табов, если блок
   это поддерживает (цикл в разметке). Нельзя менять число колонок, раскладку, порядок частей.
4. Не повторять один и тот же блок дважды подряд по смыслу.
6. **Не менять число карточек в блоках с фиксированной композицией** (замечание владельца, 2026-10-20):
   Platform Bento — теперь универсальный блок (см. §3.1 и стресс-кадры в группе «Универсальные блоки» картотеки):
   верхняя карточка, audit, 1–3 карточки пары, ноутбук и сводка — все необязательные. Сетки карточек (Checks,

## 6. Картинки

- Сначала ищи подходящую существующую в `img/` (`ls img | rg …`) — иллюстрации шагов, иконки,
  карты, флаги. Существующие файлы **не переименовывай, не удаляй, не пережимай** (особенно `*.png.webp`).
- Нужна новая картинка, которой нет (скриншот продукта, иллюстрация из ТЗ) — **не рисуй и не
  генерируй**. Временно поставь самую близкую существующую и запиши в карту и отчёт строку:
  блок · имя будущего файла `img/<slug>-<что>.webp` + `@2x` · размеры 1x · что изображено (из ТЗ) · alt.
- Если картинку предоставил владелец — конвертируй в WebP 1x/2x (`cwebp -q 86`), имя `<slug>-<что>`.
- **Генерация через Magnific — только по прямому указанию владельца** (тратит кредиты аккаунта):
  `python3 /Users/dmitriy/ZAKAZI/nv.global/tools/magnific_generate.py --prompt "…" --aspect widescreen_16_9 --out <scratchpad>/<slug>-<что>.png`
  (ключ берётся сам из `~/.config/magnific/key`; не читать и не выводить его). Промпт — по описанию из ТЗ,
  без реальных людей и логотипов, тестовые имена. Исходник — в scratchpad, в тему — только WebP 1x/2x.
  Каждую сгенерированную картинку показать владельцу до вставки (если владелец не разрешил вставлять сразу —
  тогда лист превью всех новых картинок обязателен в отчёте).
- **Опыт AML (обязательно):**
  - Генератор не пишет читаемый текст — получается абракадабра. Любой элемент с текстом (карточка результата,
    экран дашборда, таблица) — **HTML-макет со шрифтом Satoshi** (`fonts/Satoshi_Complete/Fonts/WEB/fonts/`),
    отрендеренный Playwright в PNG (`omitBackground: true` для прозрачного фона), тексты — из ТЗ, имена тестовые.
    В промпте генератора: «no text, no letters, abstract placeholder lines».
  - **Hero** (`.main__media`, текст поверх левой половины, факты справа ≥992): человек/объект — в центре-справа
    (≈50–80% ширины), левые ≈45% — спокойный размытый фон. Карточку с текстом накладывать только на desktop-кадр
    (≥992) в зону ≈42–67% ширины; для 768–991.98 Identity кадрирует картинку (`left:-24.87%; width:150.8%`) — дать
    отдельный `<source>` без наложений; для <768 — свой кадр 720×536 без наложений (кнопки лежат на фото).
    Размеры: 1600×1056 + @2x, mobile 720×536 + @2x, WebP ≤120 КБ (1x).
  - **3D-иконки** (шаги 200×200, промо): стиль существующих — глянцевый оранжевый #FD6B01 + белый, без текста,
    `--remove-bg`, обрезать по альфе и вписать в квадрат 400 (@2x) / 200 с полями ~6%.
  - **Анатомия и качество (О-18):** перед вставкой смотреть увеличенные фрагменты — руки и пальцы (по 5, без
    слипания/лишних суставов), лица, глаза, предметы в руках. Дефект — генерировать заново, не вставлять. Генерировать
    в 4k (`--resolution 4k`): @2x получается уменьшением, а не растягиванием; мягкие результаты не принимать.
    Лучше композиции, где руки небольшие. Для людей в кадре — до 3 попыток, если дефекты анатомии.
  - Не тратить кредиты на перебор: не больше 2 попыток на картинку; если обе плохие — оставить подходящую
    существующую и записать в карту.
  - Существующие картинки, подходящие по смыслу (паспорт, чек-лист, маскот), не заменять ради замены.
  - Проверять каждую картинку в предпросмотре на 1920 / 1440 / 840 / 392.
- alt — дословно из ТЗ. Декоративные — `alt=""` + `aria-hidden="true"` (как в источнике).
- Первый экран — без `loading="lazy"`; остальные — `loading="lazy" decoding="async"`, с `width`/`height`.
