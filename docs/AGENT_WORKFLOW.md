# NV Global — режим работы AI-агентов

Установлен 2026-10-16 по указаниям владельца. Этот документ задаёт текущий процесс;
исторические записи в остальных docs не являются подтверждением текущего состояния.

## Роли и модели

- Координатор — текущий основной агент: анализ запроса/Figma, аудит reuse, полное ТЗ,
  передача исполнителю, независимая проверка кода и браузера, follow-up и вердикт.
- Один постоянный исполнитель — Claude Code (`claude`), `claude-sonnet-5`, reasoning `high`.
  Это явный проектный выбор владельца, уточняющий общий Traycer agent selection guide,
  где по умолчанию рекомендован Opus. При существенном архитектурном затруднении
  координатор предлагает переход на доступный Opus; не меняет модель молча.
- Необязательный QA Reviewer — только для сложной работы или shared-компонентов:
  `claude-opus-5`, reasoning `xhigh`, независимая проверка, без реализации.
- Figma Auditor — только для действительно большой страницы, когда отдельный аудит
  оправдан; без кода. Одновременно по умолчанию работает один исполнитель.
- Сборщик страниц (с 2026-10-20, по указанию владельца) — постоянный агент, собирает новые
  страницы из блоков библиотеки по ТЗ; `claude`, Opus, reasoning `high`. Работает по
  [PAGE_BUILDER.md](PAGE_BUILDER.md), читает его перед каждой страницей; память по странице —
  `docs/pages/<slug>.md`. Блоки и CSS не меняет — доработки блоков идут через координатора.
- Не создавать агентов под PHP/CSS/JS/mobile/docs. Не создавать агентов при одном
  обсуждении схемы. Реальный запуск — при поступлении задачи на реализацию.
- Перед созданием агента проверять доступность модели и параметры Traycer.
  Исполнителю передавать skill `traycer-implement`, отдельному reviewer — `traycer-review`.

## Цикл задачи

1. Пользователь передаёт цель, Figma URLs/node IDs и ограничения.
2. Координатор выполняет `git status`, фиксирует исходный diff и существующие изменения.
   Находит canonical template и нужные области PHP/CSS/JS через rg.
3. Читает каждый full-page Figma node один раз, фиксирует реальную ширину и states;
   проверяет reuse Home / Solutions / KYC / Pricing / Blog / template parts.
4. Готовит в артефакте задачи полное исполнимое ТЗ: goal, nodes, scope, карта
   section → existing implementation → reuse/variant/new, данные WordPress,
   interactions, responsive, accessibility, visual/functional/technical QA,
   regression, Git/docs, token economy и формат отчёта.
5. Если задача на реализацию уже поручена, передаёт ТЗ исполнителю без повторного
   запроса разрешения. Если запрошен только проект ТЗ — реализацию не запускает.
6. Исполнитель работает в текущей теме, сохраняет исходные пользовательские правки,
   делает self-QA и возвращает один отчёт. ТЗ и отчёт передаются через артефакт/путь,
   с коротким сообщением, без копирования всей истории переписки.
7. Координатор проверяет фактический diff, браузер, соответствие Figma, динамику
   WordPress, доступность, responsive и regression. Самоотчёт не заменяет проверку.
   Для визуальной работы действует [VISUAL_ACCEPTANCE.md](VISUAL_ACCEPTANCE.md):
   overview+detail, внутренняя структура, матрица coverage и проверка настоящего URL.
8. При дефектах создаёт короткий follow-up: ID, URL/state/viewport, expected/actual,
   evidence, требуемая коррекция и проверка. Отправляет тому же исполнителю.
   Закрытые требования заново выполнять не нужно.
9. После доработки проверяет замечания и затронутые зависимости. Повторяет цикл
   до прохождения проверок. При повторении одной причины после двух доработок
   пересматривает диагноз и при необходимости привлекает QA Reviewer; не гоняет
   одинаковые prompts бесконечно. Внешние блокеры сообщает пользователю.
10. Выдаёт READY TO ACCEPT / FIXES REQUIRED / NOT READY с основаниями.
    READY TO ACCEPT — рекомендация; окончательная приёмка остаётся за владельцем.
    Статус локального исправления не повышает автоматически статус всей страницы.
    Page-level READY требует закрытой матрицы обязательного scope без пробелов
    и несогласованных отклонений; см. VISUAL_ACCEPTANCE.

## Неприкосновенные ограничения

- Reuse before new code; при совпадении 80–90% использовать компонент или variant.
- Header/Footer глобальные, вне scope страницы; не подгонять под старые версии в Figma.
- Сохранять WP queries, данные, ACF, pagination/search/taxonomy и формы.
- Не добавлять параллельную CSS/JS архитектуру, вторую slider-библиотеку и refactor заодно.
- Не менять БД, публикацию страниц и production-настройки без поручения.
- Формы локально не отправлять: backend может слать реальные письма/Telegram/HubSpot.
- Не выполнять commit/push/merge/rebase/deploy автоматически, включая после READY TO ACCEPT.
- Не откатывать и не перезаписывать исходные изменения. Один агент пишет код;
  координатор в это время проверяет, не редактируя те же файлы.

## Проверка и evidence

Локальный URL по документации — https://nvglobal.local/; MAMP, самоподписанный TLS.
Перед работой сверять окружение, не считать прежние версии и пути актуальными без проверки.

Visual QA: одинаковые viewport и состояние страницы/Figma, дождаться шрифтов и изображений;
side-by-side и overlay/diff ключевых секций. Базовые эталоны 1920 / 1440 / 840 / 392,
только при наличии соответствующего макета. Нет Mobile — явно указать выводимый
адаптив, не заявлять подтверждённое совпадение с Figma.

Автоматический responsive sweep (bounds/overflow, базовые компоненты):
1920, 1600, 1440, 1366, 1200, 1024, 992, 840, 768, 576, 478, 420, 392, 375, 320.
Визуально проверять reference modes, пары границ и середины затронутых media;
на локальных ретестах сохранять достоверные прежние проверки по карте зависимостей,
не повторять весь15ширинный sweep. Проверить states, keyboard/focus/touch,
overflow, console/network, images, duplicate IDs, семантику. PHP lint изменённых PHP,
JS syntax изменённого JS, CSS balance; функциональные проверки по scope.

Регрессия определяется зависимостями: shared-компонент → все места использования;
page-only → целевая страница и релевантный smoke набор. Проверка пустого блога
не доказывает работу pagination/search с реальными записями; непроверенное указать.
Временные DOM fixtures доказывают только вёрстку.

Отчёт: files, reuse/new, viewport/states, команды и результаты QA, regression,
ссылки на скриншоты/сравнения, deviations, blockers и непроверенные пункты.
Непроверенные обязательные требования не помечать пройденными.

## Состояние между задачами

Артефакт задачи хранит ТЗ, Figma IDs, reuse-карту, ревизии, замечания с ID,
evidence, вердикт и факт пользовательской приёмки. Статусы:
подготовка → реализация → проверка → доработка → готово к приёмке → принято.

PROJECT_STATE — краткий актуальный срез; COMPONENTS — shared/variants;
QA — реальные результаты и ограничения; CHANGELOG — выполненное;
DECISIONS/BACKLOG — только новые решения/известный долг.
Не дублировать журнал каждого цикла во всех документах.

## Экономия контекста — уточнение владельца

Для точечной правки читать только относящиеся к ней строки, передавать исполнителю
короткий follow-up и проверять изменённый элемент. Не повторять полный аудит,
Figma full-page reads и закрытые QA; отдельного QA Reviewer для мелких правок
не подключать. Короткий итог без повторения предыдущих отчётов.

По замечанию владельца о пропущенных дефектах: экономия не отменяет overview+detail
и внутренние критерии. После систематических возвратов сделать один согласованный
проход по непокрытым критериям/семейству причины, сохранить реестр и затем выполнять
только адресные ретесты. Это не основание гонять всю страницу после каждой правки.

## Параллельная работа нескольких верстальщиков (с 2026-10-21, по указанию владельца)

Все верстальщики одинаковые (claude / sonnet / high, рабочая папка — тема) и работают по одним правилам:
этот документ, `CLAUDE.md`, `docs/FRONTEND.md`, `docs/WORDPRESS.md`, `docs/OWNER_REMARKS.md`, ТЗ —
артефакт `block-catalog/universal-blocks`. Каждому координатор выдаёт **один блок** и его границы.

**Свои файлы** (правит только владелец блока): `template-parts/<блок>-section.php`, `css/blocks/<блок>.css`,
стресс-кадры `inc/bloki-stress/<блок>.php` (файл возвращает `slug => array('part' => …, 'args' => …)`;
`inc/bloki-stress.php` подмешивает их сам — сам `inc/bloki-stress.php` не трогать).

**Общие файлы — только точечно и только свою секцию:** `page-*.php` (вызов своего блока; перед каждой правкой
перечитать файл, правка — `Edit` по уникальному фрагменту, после — `grep`, что своя правка на месте и чужие не
пропали). `inc/*-data.php` — только данные своего блока.

**Не трогать никому, кроме интегратора (Верстальщик-1):** `THEME_ASSETS_VER`, `functions.php`,
`inc/css-registry.php`, `inc/bloki-data.php` (картотека), `docs/CHANGELOG.md`, `docs/PAGE_BUILDER.md`,
`docs/COMPONENTS.md`, `docs/DECISIONS.md`. Нужное для них — текстом в отчёте.
`js/main.js` — без согласования с координатором не менять: разметка, `data-*` и классы, на которые опирается JS,
сохраняются.

**Проверки:** свой блок — стресс-кадры + все страницы, где он стоит, 14 ширин
(1920/1665/1600/1440/1366/1200/1100/992/840/768/740/576/392/320), скрипты `/Users/dmitriy/ZAKAZI/nv.global/tools/css-qa/`
и `check.js` по образцу пилота. Сайт общий: соседи правят его одновременно — проблема в чужом блоке не чинится,
а указывается в отчёте. Итоговый прогон по всем страницам — после всех, по команде координатора.

**Отчёт** — ответом координатору: файлы, аргументы partial, страницы, проверки и снимки (пути вне темы),
не проверено, тексты для картотеки и CHANGELOG. Без коммитов; чужие незакоммиченные правки не откатывать.
