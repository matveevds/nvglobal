# Визуальная приёмка NV Global

Действующий регламент, введён по замечанию владельца о пропущенных расхождениях.
Применяется совместно с AGENT_WORKFLOW. Приоритет — прямые инструкции владельца.
Не читать повторно целиком перед каждой CSS-правкой: хранить актуальные критерии
в ТЗ и использовать соответствующий раздел этого документа.

## Что считается проверкой

Отсутствие ошибок, docOverflow=0, корректная внешняя ширина секции и самоотчёт
исполнителя **не доказывают соответствия макету**. Сгенерированная пара screenshots
тоже не является просмотренной. Координатор отвечает за независимую сверку.

Три разных источника не смешиваются:

1. **Эталон** — конкретный Figma node/state/mode и официальное изображение.
2. **Прототип** — временная DOM/CSS-инъекция, проверяющая механизм.
3. **Результат** — настоящий URL с текущими production-файлами, без инъекций.

Размер прототипа нельзя записывать в колонку Figma target. Совпадение результата
с прототипом подтверждает механизм, но не заменяет сравнение с источником.
Generated JSX fallback tokens и XML без transforms не заменяют resolved mode values.
**Каждый числовой target имеет provenance:** node + reference mode + свойство/variable
либо source-derived contract-файл с этим происхождением. Для variable-bound свойств
всегда использовать resolved mode value, даже когда JSX fallback выглядит однозначным.
Для transforms хранить rotation/mirror/crop и систему координат. Число без provenance
не является эталоном и не закрывает проверку. Сначала использовать кэш; недостающее
адресно читать у дочернего node, не перечитывая full-page. DOM-proof не provenance Figma.

## Два масштаба сравнения

- **Обзор секции**: композиция, порядок, колонки, высота по контенту, соседние секции,
  полные верхняя/нижняя границы, широкие и узкие состояния.
- **Детали**: crop в масштабе1:1 или достаточно крупный для чтения исходного текста,
  иконок, рамки и скруглений. Проверять небольшие callout, badges, controls, автора,
  края и другие элементы, которые не видны на обзорном уменьшенном изображении.

Contact sheet и длинный screenshot — навигация по evidence, а не самостоятельное
основание визуального PASS. Сравнивать одинаковые viewport/state, дождаться шрифтов,
decode нужных изображений и завершения resize/snap/transition. Масштабировать обе
половины одинаково по ширине, не растягивать высоту для искусственного совпадения.
Скрывать sticky widgets допустимо только в QA DOM и с одинаковыми условиями; рамки,
page-edge и внутренний padding секции при сравнении не вырезать.

## Проверять внутри каждого компонента

До PASS составить **перечень проверок из структуры источника**, а не из собственной
разметки: для каждой вложенной auto-layout группы её node, row/column, порядок, gap
и align; для каждой поверхности — fill, стороны stroke и направление скруглений;
для текстов/изображений — связанные mode/transform targets. Повторяющийся instance
с одинаковыми свойствами можно сгруппировать, но отличающиеся modes/states перечислить.
Это компактная source-derived inventory секции, связывающая атрибуты с evidence.
Одна crop без названных проверенных атрибутов не закрывает detail. Непроверенный
пункт inventory = NOT CHECKED, а не PASS всей секции.

| Критерий | Что реально проверить |
| --- | --- |
| Структура | row/column у вложенных icon+text, DOM/визуальный порядок, align/justify, переносы и расстояния, размещение controls |
| Типографика | resolved font/weight/size/line-height, ширина текста и строки, mode overrides и специфичность; не уменьшать шрифт ради fit |
| Поверхности | цвет фона, border/inside stroke, радиус и направление углов; различать серую островную панель и белые page-edge поверх серого |
| Изображения | исходник, aspect, mirror/rotation, внутренний crop, реальные размеры absolute SVG; подписи не закрыты непрозрачной частью |
| Данные | реальные WP-данные; placeholders Figma не считать обязательным production-контентом; длинные/пустые состояния по scope |
| Границы | inset первой карточки и внешняя граница clipping проверяются отдельно; component bounds внутри окна, не только document scrollWidth |

Внешний bbox правильного размера не закрывает внутреннюю структуру. Проверять
все различающиеся карточки/варианты, а не одну «похожую». Элемент с одинаковыми
классами на двух страницах не доказывает reuse разметки и одинаковый responsive.

## Поведение и промежуточные ширины

- Два разных набора: **автоматический sweep** —15ширин AGENT_WORKFLOW для bounds/
  overflow и базовой доступности компонентов; **визуальный** — предоставленные
  reference modes плюс пары границ и середины затронутых диапазонов. Между reference
  widths проверять инварианты адаптива, не заявлять совпадение с отсутствующим Figma.
  Fixed-basis/max-width и специфичные широкие правила проверять внутри диапазона
  и с обеих сторон границы. На локальном ретесте запускать только затронутый scope
  и зависимости; исходный15ширинный проход не повторяется после каждой CSS-правки.
- docOverflow=0 не закрывает обрезанную карточку: измерять видимые component bounds
  относительно контейнера/экрана, затем смотреть screenshot.
- Слайдер: initial после загрузки, первая/последняя карточки, ручной swipe, кнопки,
  resize между режимами; **после settle** выбранный шаг, aria и видимый результат
  должны соответствовать. Проверка только положения в момент click недостаточна.
  Settle означает scrollend/transitionend с последующей стабильной геометрией
  либо неизменные rAF-замеры scrollLeft/transform/rect затронутого компонента
  не менее300мс. Сразу после этого вместе сверить active/aria/видимую карточку.
  То же условие применять после resize; фиксированный sleep сам по себе не доказательство.
- Tabs/accordion: все предоставленные states, первый/последний, keyboard/focus и
  no-JS, если это требование компонента. Fixtures подтверждают только свои сценарии;
  реальный URL/data path проверять отдельно.
- CSS position/transform/overflow меняют offsetParent, stacking и clipping.
  Проверять зависящие интеракции после изменения, даже если JS-файл не менялся.

## Как определять зависимости CSS

Для каждого изменённого селектора зафиксировать совпавшие элементы и canonical
контексты страниц из COMPONENTS/вызовов partial/body-классов. Проверять contexts,
а не все URL записей с одним шаблоном. Если элемент не совпал с селектором, правило
не считается проверенным. Identity scope не заменять предположением «класс тот же».

Через matched styles/CDP (либо эквивалентную вычисленную проверку) проверить для этих
элементов выигравшее правило и ближайшие более узкие media: специфичное широкое
правило может перебить слабый Mobile reset без новой строки в diff. Для изменённых
position/transform/overflow/z-index проверить offsetParent, stacking/clipping предков
и затронутые controls. Итоговая краткая карта:

`changed selector/property → matched element/context → narrow overrides/ancestors → retest`.

Этот перечень, а не только список файлов, определяет какие прежние PASS сохраняются.
Делать один адресный probe на класс эквивалентных элементов/контекстов, переиспользовать
уже сохранённые данные; не читать/рендерить весь repository и все WordPress-записи.

## Реестр и допуск к приёмке

Полная матрица обязательна для страницы с **6и более секциями**, а также для изменения
shared partial/его общего поведения (для shared — только затронутые секции и contexts).
Для меньшей изолированной задачи достаточно строк по её компоненту/режимам. В артефакте:

`section → viewport/state → source inventory/provenance → overview/detail evidence → visual result → functional result → version → open IDs`.

PASS ставится после просмотра и требуемой проверки, с опорой на настоящий результат.
Статусы: PASS / FIX / NOT CHECKED / NOT APPLICABLE с кратким основанием.
Эталон и evidence должны относиться к той же версии либо быть явно сохранёнными
проверками неизменённых правил **и зависимостей**. NOT CHECKED нельзя превращать
в PASS фразами «reuse», «ничего не меняли», «нет времени».

**Локальное исправление и готовность страницы — разные выводы.** После точечной
правки писать «U-03 проверен». READY TO ACCEPT всей страницы допустим только когда:

1. Матрица обязательного scope закрыта; все известные требования и замечания учтены.
2. Есть независимо просмотренные overview и нужные detail crops всех секций/режимов.
3. Functional/responsive/regression покрыты по зависимостям.
4. Нет обязательных NOT CHECKED или несогласованных deviations; исключения владельца
   записаны явно. Разницу antialias не выдавать за дефект без проверки причины.

READY — рекомендация, не пользовательская приёмка. Генерировать предложение
«принимаю» вместо незавершённого review нельзя. При новой претензии владельца
готовность затронутого scope отзывается до повторной независимой проверки.

## Работа с повторными замечаниями и экономия

После двух возвратов по одной причине исправлять диагноз/критерий, а не повторять
тот же prompt. Проверить **семейство причины** в текущем scope: неверный axis →
вложенные группы на затронутых modes; clipping → соответствующие края/controls;
mode override → аналогичные селекторы. Составить один консолидированный остаток.

Существующий независимый QA Reviewer подключается для сложной страницы/shared
изменений или систематических пропусков. Новых агентов автоматически не создавать;
не дублировать весь аудит двумя исполнителями. Назначать reviewer конкретную часть
матрицы/слепую зону, затем объединять результаты координатором.

На большую страницу нужен один финальный согласованный проход перед передачей
владельцу. При локальной правке переиспользовать достоверные предыдущие PASS и
проверять только изменённое плюс зависимости. Кэшировать Figma, измерения, пары,
матрицу и открытые ID. Один итоговый отчёт; не делать fullsweep после каждого CSS.
Экономить повторные чтения и дублирование отчётов, а не обязательную визуальную сверку.
