# CLAUDE.md — тема nvglobal

Рабочая WordPress-тема живого сайта.

**Основной режим: прямой редизайн существующей темы по Figma.**
Правим существующие PHP-шаблоны, `css/styles.css` и `js/main.js` прямо в теме.
Отдельных статических HTML-страниц не создаём.

**Отвечать всегда на русском.** Код, имена файлов, CSS-классы и HTML-атрибуты не переводить.

## Этапы

1. **Аудит** — выполнен 2026-10-05, результаты в `docs/PROJECT_STATE.md`.
2. **Решения по реорганизации** — приняты 2026-10-05, зафиксированы в `docs/DECISIONS.md`.
3. **Редизайн по Figma** — текущий режим. Ждём ссылки на макеты.

Разные этапы — разные коммиты. **Глобальные и локальные изменения — тоже разными коммитами.**
Не смешивать рефакторинг с визуальными правками.

## Режим редизайна — короткий свод

Полный текст — `docs/DECISIONS.md`. Главное:

- Сохранять WordPress-логику, структуру блоков, БЭМ-классы и функциональность.
- Не копировать шаблоны целиком, если можно изменить существующий.
- Не рефакторить попутно. Переиспользовать существующие компоненты.
- Новые токены — только после анализа конфликтующих значений и мест использования.
- Нет Tablet/Mobile макетов → **сохранять существующий адаптив**
  (`docs/FIGMA.md` → «Работа с Desktop-only макетами»).
- После каждой секции — проверка в Playwright на всех пяти вьюпортах + сверка с Figma.
- **Визуального сходства недостаточно, если сломана функциональность WordPress.**

## Перед любой правкой

1. Прочитать `docs/PROJECT_STATE.md` и `docs/COMPONENTS.md` — найти, где секция уже реализована.
2. Проверить, нет ли готового компонента/модификатора/токена (`docs/FRONTEND.md` → «Переиспользование»).
3. Кратко описать план. Только потом править.
4. После работы — список изменённых файлов + запись в `docs/CHANGELOG.md`.

## Запрещено без явного указания пользователя

- Рефакторинг, переименование классов, объединение и удаление файлов.
- Менять `header.php` и `footer.php`.
- Подменять `get_field()`, `have_rows()`, `get_sub_field()`, `the_content()`, `WP_Query` статикой.
- Удалять `esc_html` / `esc_attr` / `esc_url` / `wp_kses`, nonce-проверки, capability checks.
- Вводить CSS-фреймворк, новую систему именования, новые брейкпоинты или новые каталоги ассетов.
- Переносить media-запросы в конец файла или собирать их в общий блок.
- Объявлять `:root`-переменные для токенов `--island-*` / `--stroke-*` / `--text-*`
  (см. `docs/THEME-TODO.md` → «Необъявленные токены» — это сломает цвета разом в 384 местах).
- `git reset`, `git clean`, `git checkout --`, `git push`, деплой, миграции БД,
  переключение темы, обновление плагинов.
- Удалять файлы из `img/`. Чистка отложена до конца редизайна (`docs/DECISIONS.md`, Р-1).
  Особенно **не трогать `*.png.webp`** — это живые WebP-двойники Seraphinite, а не мусор.
- Изменять production-сайт.
